# Local maintenance build 6.0.0-owen.6

If directory removal fails, code folders previously disappeared from runtime state before the disk operation completed. Notes and HTTP folders suppressed the removal error and returned success. All three domains now propagate the disk error and remove folder records only after directory removal succeeds. The shared removal helper no longer accepts an option to suppress this error.

Three regression cases inject a failed disk deletion, verify the folder list is retained, then retry successfully. The focused folder and Windows file-availability suites pass 41 cases. Existing resource limits, successful-update index repairs, vault/profile and disabled API/MCP settings are retained. Multi-file deletion still uses the existing per-record trash operations; this does not claim an atomic transaction or rollback of records already moved before a later failure.

The formal Windows runtime remains based on upstream 6.0.0. Source commit, compiled-module hashes, installed archive SHA and two-machine adoption are recorded in the installation maintenance receipts. Native GUI, real cloud hydration and long-run acceptance require separate evidence.
