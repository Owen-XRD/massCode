# Local maintenance build 6.0.0-owen.3

The previous installed build was 6.0.0-owen.2. These fixes were retained in the October 11 source candidate but had not reached the installed archive. This release preserves the existing vault, device profile, secrets, Syncthing folder and demand-start desktop entry.

- Search results preserve their existing semantics while the LRU retains at most 64 queries and 16,384 result IDs. Large queries/results still execute without entering the cache.
- HTTP console diagnostic and redacted AI copies share the 32 MiB accounting budget. Each copied tree has bounded text, keys, depth and nodes; clearing/pruning releases both copies.
- Gist reads count actual streamed bytes and cancel an oversized response. Markdown import walks directories serially, bounds retained input and closes handles on rejection. ZIP overflow destroys the inflater instead of leaving a paused worker; ordinary files share its aggregate expansion budget.
- Uploads are bounded before retaining bodies, multipart fields share a 16 MiB payload budget, and an oversized file does not prevent a later small request.

These are resource limits, not content keyword filters. Stored documents/history remain business data; the full application has no global RAM cap. API/MCP integrations and optional AI remain disabled in the user's deployment.

The focused resource regression covers successful results, eviction, overflow cancellation and recovery. TypeScript baseline/candidate comparison retains one pre-existing external diagnostic and requires zero introduced diagnostics. Packaging binds every retained overlay to its source/compiled hash and the actual installed ASAR. Exact checks, both-machine adoption, budgets and archive hashes belong to the installed project's `work/resource-review-20261015` receipts.

No foreground GUI is opened for this maintenance. Installed-module/headless evidence does not establish physical GUI, reboot, long-run or all-import-format acceptance. The prior .2 artifact and original official recovery package remain available.

Maintenance entry scripts import Windows PowerShell modules from their own PSHOME, so a Core parent's PSModulePath cannot hide Get-FileHash or ScheduledTasks. The activation helper follows the selected VERSION/LOCAL_PATCH identity by default and obtains process metadata without the optional WMI query. The .1 formal artifact is preserved as a member-hash-verified archive; .2 remains an immediately launchable rollback.
